# Contributing

Start with `CLAUDE.md` for the working rules that will bite you (destructive
seed, append-only tables, metric version bumps) and `docs/decisions/` for the
ADRs behind them. The CI workflow runs lint, typecheck, migrate + seed, the
test suite, the IQ script, and both app builds; `pnpm test` locally covers
most of it.

## Documentation

The published site lives in `site/` (Astro Starlight) and deploys to
https://tgerke.github.io/dmops-core/ on pushes to `main`.

```bash
pnpm --filter site dev      # local docs at http://localhost:4321/dmops-core/
pnpm --filter site build    # what CI runs; fails on broken internal links
```

Two page groups are generated at build time by `site/scripts/sync-generated.mjs`
and are gitignored: the ADRs (from `docs/decisions/`) and the milestone
taxonomy reference (from `taxonomy/milestone_definitions.yaml`). Edit the
sources, never the synced output. `docs/validation/` is likewise generated
(`pnpm validation:artifacts`) and never hand-edited.

## Refreshing docs screenshots

Every image on the site is generated by `scripts/screenshots.mjs` against the
seeded demo, so a UI change is one command away from updated docs:

```bash
pnpm install
npx playwright install chromium   # first time only
pnpm screenshots --yes
```

The script reseeds the database first (that is what makes re-runs
reproducible), creates the one reference state the seed lacks (a re-baseline
on DMOPS-001's interim lock, so the `⟲1` badge renders), starts `pnpm dev` if
it isn't running, and captures every PNG in `site/src/assets/screenshots/`
at 2x resolution. Never point it at a database whose contents you care
about — `--yes` is the acknowledgment of the reseed.

`--only name,name` re-captures specific shots (names are the PNG basenames).
Commit the changed PNGs with the change that altered the UI.
